# Functional Requirements

> Requisitos funcionales obligatorios de la versión actual de GorilaType: qué debe hacer el sistema.

**Última actualización:** 2026-07-16
**Autor(es):** Equipo GorilaType

---

## 1. Requisitos funcionales obligatorios

| ID | Nombre | Descripción |
|---|---|---|
| RF-01 | Registro e inicio de sesión | Permitir autenticación de usuarios. |
| RF-02 | Pruebas de mecanografía | Permitir realizar tests de escritura. |
| RF-03 | Modos de juego | Permitir distintos tipos de pruebas. |
| RF-04 | Captura de teclado | Detectar teclas presionadas en tiempo real. |
| RF-05 | Validación de caracteres | Comparar la entrada del usuario con el texto esperado. |
| RF-06 | Retroalimentación visual | Mostrar caracteres correctos e incorrectos. |
| RF-07 | Cursor dinámico | Avanzar automáticamente en el texto. |
| RF-08 | Control de tiempo | Gestionar inicio y fin de la prueba. |
| RF-09 | Cálculo en tiempo real | Calcular WPM y precisión durante la prueba. |
| RF-10 | Uso de backspace | Permitir corregir errores. |
| RF-11 | Finalización automática | Detectar cuando termina la prueba. |
| RF-12 | Registro de resultados | Guardar resultados de cada prueba. |
| RF-13 | Indicador de palabra actual | Resaltar la palabra en curso. |
| RF-14 | Reinicio rápido | Permitir reiniciar la prueba fácilmente. |

> Los requisitos funcionales planificados para versiones futuras, y los opcionales, están documentados por separado en [`future-requirements.md`](./future-requirements.md) para no mezclarlos con el compromiso actual del proyecto.
