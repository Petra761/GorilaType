# Historias de Usuario — GorilaType

> Ubicación prevista en el repo: `docs/04-historias-de-usuario/README.md`

Este archivo actúa como índice de las historias de usuario del proyecto y define la plantilla que deben seguir.

## 1. Plantilla

```markdown
# GT-XX — <Título corto de la historia>

**Como** <rol>
**quiero** <acción concreta>
**para** <beneficio/motivo>

## Criterios de aceptación

- [ ] Criterio verificable 1
- [ ] Criterio verificable 2
- [ ] Criterio verificable 3

## Notas técnicas (opcional)

Detalles de implementación relevantes, si los hay.
```

## 2. Reglas para redactar historias

- Cada historia representa **una sola necesidad**. Si una historia describe más de una acción independiente entre sí (ej. "quiero loguearme y hacer el test"), se separa en dos historias distintas.
- El título corto debe alcanzar para identificar la historia sin leer el detalle completo.
- Los criterios de aceptación deben ser verificables (se puede marcar como cumplido o no cumplido sin ambigüedad).
- El ID (`GT-XX`) corresponde al ticket de Jira asociado, ver [docs/02-flujo-de-trabajo/jira.md](../02-flujo-de-trabajo/jira.md).
